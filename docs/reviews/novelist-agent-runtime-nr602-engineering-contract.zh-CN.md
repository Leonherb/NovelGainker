# NR-602 分支、归档清空与导出工程合同（实施中）

前置 NR-601 完整 quality 已通过（32 步）；继续用户批准的连续实施，不开放真实 Provider、自动分发或最终 G7。

- 结构动作只有 branch / clear / archive / restore。均受工程目录 CAS、同工程活动生成排除、既有 32 非归档/256 总条目及三类总容量限制，不隐式停止生成。
- 分支只接受原会话中已经持久的终态 Turn 边界；复制截至该边界的可见消息，重新生成 Session/Turn/Message 身份，不复制 Memory、Task、Change、出版回执或工具续传状态，也不回滚当前共享 Canon。
- 分支/清空使用稳定请求 UUID。Host 根据工程 ID、动作、请求 ID、原会话、边界和初始名称派生目标 UUID，并校验同请求既有结果；重复点击或确认丢失不产生第二份可见会话。准备文件存在时只有精确匹配预期字节才能复用，绝不覆盖不明文件。
- 清空先准备一个新空会话及容量，再用一次目录原子提交归档原会话并挂载新会话；32 个非归档时清空仍为 32 个。失败保留旧目录/历史，孤立准备文件计入配额。归档释放的是名额，不是磁盘；不提供永久删除。
- 归档可只读查看，恢复需要空闲名额且不执行旧工具。新会话不能确认原会话的待确认操作；原 Undo 必须明确原会话作用域并核对现行 Canon 的 afterHash。
- 显式导出仅 Markdown/JSON 可见对话，包含其中用户自己输入的内容，界面须提醒检查隐私；不导出隐藏提示、Memory、Task 原始数据、工具参数/响应或凭据。单次导出上限 32 MiB。
- 导出通过原生保存对话框选择准确目标；Host 持有最多一份、有效期五分钟的有界一次性 token，IPC 不接收任意路径或替换字节。最终写入再核对来源快照、父目录/重解析边界，不进入当前或已登记小说工程，不创建父目录，不覆盖已有文件；同目录临时文件加无覆盖原子提交，失败不删除旧文件。回执仅给安全文件名、字节数和 SHA256，不给绝对路径。
- 拟增加三个封闭 IPC：conversation_session_manage、conversation_export_prepare、conversation_export_commit；五层契约同步后共 37 项。只允许在冻结 NR-601 全质量证据存在时挂载。目录/list 等旧 Gate 基线和历史证据保持独立。
- UI 沿用聊天区域工具条，渐进展开归档、分支与导出。清空前明确说明可恢复和共享资料不变；归档只读状态、名额耗尽、失败后重试均可见，不增加 Task/History 中心。
- NR-602 安全复核补充：没有物理工程 writer lease 的另一实例只能读取既有目录/History/Task，不初始化、不恢复另一实例的活动 Turn，不改名/激活/发送。若旧工程尚无目录，须由写入实例先初始化，当前只读实例显示不可读取，不生成新身份。SessionPage 严格新增 canMutate。相同进程的工程别名可共享物理 lease，但不增加 Canon 权限；后台 worker 持有该 lease 至最后落盘，即使窗口已关闭。
- 导出准备与提交都占用同一个内存槽。准备/写入期间不能靠过期或再次点击产生另一份缓冲区；关闭工程使未提交凭证失效，已明确提交的写入完成后释放槽。原生选择过程中若工程被关闭，选择返回后拒绝完成准备。导出函数只接受 Host 工程句柄集合，不暴露工程绝对路径 API。
- 当前定向结果：14 项 Rust/桌面桥接测试、34 项本 Story 授权负例、7 项会话界面测试（含 4 项新增）、3 项新 DTO 测试通过。跨实例验证为独立 registry + 真实 OS writer lease；保存选择结果由夹具替代，提交经过实际 IPC 和文件系统。没有声称原生对话框实际点击或多用户测试完成。
- 验证包括终态边界/新身份/无重放、32 满额原子清空/恢复拒绝、256 总目录、幂等/CAS/故障残留、旧来源回执与 Undo、导出可见字段/取消/过期/重复/同名/重解析/磁盘错误，以及完整 quality。当前文件不表示上述验证已经通过。
