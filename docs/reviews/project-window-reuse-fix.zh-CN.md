# 重复打开工程：复用已有可写窗口

日期：2026-09-08。用户要求先修复同工程重复打开只能只读的问题，再使用 test2 测试工具保存。本记录不改变历史 Gate 结论。

## 行为

采用已向用户说明的默认方案：重复打开同一工程时切回已有可写窗口继续编辑。项目打开与最近项目入口均在写锁被占用时尝试激活已有窗口，不注册新的只读会话。旧测试版未注册窗口或系统拒绝前台激活时，明确提示已有工程窗口及关闭旧工程后重试。

Windows 窗口注册绑定现有工程写锁的协调键，生命周期随已打开工程；不暴露路径，不传递写锁，不增加 IPC，不允许两个独立进程同时改写工程。关闭工程后解除注册，不清除外部写锁或恢复记录。

## 证据

- 原生开发版双窗口打开 test2：第二个窗口显示“已切换到此工程的已有窗口”，原先 test2 窗口实际置前并保持单 Writer 会话。第二窗口仍未打开项目，无只读副本。
- `project_window_registration_is_scoped_and_removed_without_releasing_writer`：隐藏合成窗口验证键匹配、错误句柄、解除注册及写锁保持。
- `repeated_project_open_does_not_create_a_read_only_session`：实际桌面命令验证重复打开不新增会话，原写会话关闭后可以成功打开为可写。
- NG-104 跨进程写锁及恢复测试通过；前端覆盖两种受控返回码，确保不加载假只读工程。

限制：这是复用原窗口的方案，并非允许多个窗口独立并发写入。未生成安装包或发布包。
