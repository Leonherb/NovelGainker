## 3. 尚未批准的产品决定

### NR4-D1-R01 — 自动维护与权限

建议接受：五类资料、一个类型化变更工具；明确用户来源自动保存，建议留在聊天，歧义/冲突等待决定。九项能力不等于九个写入工具，方法读取范围不自动转成写权限。

这与已批准总计划方向一致；本次只是冻结具体实现范围，不重新辩论“是否每项都确认”。

### NR4-D1-R02 — 起步预算和撤销存储

建议接受：最多两次读取、一次四目标以内变更；正文合计 8 KiB；有界本地变更库保存候选及 Undo 快照，不保存原始 Tool/Provider 协议。

代价：较长人物卡/大纲可能只读或需手工编辑；同一 Turn 不能完成任意长的关联更新。配额耗尽需明确清理，不能静默丢失可撤销历史。该限制须进入实现后的产品说明，而不是遇到时泛称“工具不支持”。

64 MiB/100 条不是性能证据，也不是现有常量；NR-401/406 必须实测边界。接受预算提案不允许用扩大常量代替通过压力测试。

### NR4-D1-R03 — 正式章节来源（范围差异）

原总计划要求 NR-G5 证明正式章节事实可自动维护 Canon；现有产品还没有 NR-5 的正式 Chapter Commit 身份合同。只有文件 Hash 不够区分聊天稿、手工草稿和已提交正文。

建议批准明确分期：NR-4 支持用户明确指定章节事实的任务；独立 `chapter_commit` 自动来源暂不启用，留给 NR-5 建立提交身份。不得将这一建议冒充原计划已批准内容。

若不接受该分期，Draft 1 必须修订并补齐只读正式来源识别的生产路径和验收后，才能实施；不能一边保持原 NR-G5 全量声称，一边把缺口留到以后。

### NR4-D1-R04 — 既有 Live 决策

未执行正式 Provider Live Smoke。用户自己的普通聊天测试是有价值的观察，但没有双 Provider、合成工程与原生工具结果证据，不能自动写成正式 Smoke 已通过。

实施前按总计划明确选择单独授权最小只读 Smoke，或者明确放弃并接受真实兼容性未验证风险。没有凭据/网络授权时不执行；不增加 Pre-NR-4 修复计划，不重开 NR-G4。NR-6 完整写入/章节/语义验证仍独立保留。

## 4. Story 覆盖与残余风险

| 必须覆盖的用户行为                | 承担 Story       | 判定依据                                         |
| --------------------------------- | ---------------- | ------------------------------------------------ |
| 明确新角色 / 修正设定自动落盘     | NR-401～404      | 真实 Canon 字节、来源回执、Host 结果；非模型自述 |
| 只是讨论建议 / 空工程只读检查     | NR-403～404      | 零非授权写入、自然回复正常，空数据不是调用失败   |
| 已有资料持续维护 / 同名冲突       | NR-401、403、405 | 完整版本读取、身份解析、最小差异；歧义不猜       |
| 脏编辑器 / 外部编辑 / 多文件故障  | NR-402、404～405 | 缓冲保留、Hash/CAS、准确恢复状态                 |
| 待确认 / 取消 / 关窗 / 重开       | NR-402、404～405 | 不重复写、不丢非空回复、不阻塞已决定关闭         |
| Diff / Undo / 存储配额            | NR-402、404～405 | 本地回执、不可变快照、撤销前置条件               |
| 双 Provider / 有界循环 / 发布权限 | NR-403、406      | 离线 Loopback、极值请求体、自包含与权限检查      |

残余风险不是新增前置 Story：

- 模型可能误判用户意图或遗漏语义冲突；Host 客观校验、Diff/Undo 不等于语义正确性保证。
- 外部编辑器不参加应用事务，无法承诺多文件全球原子性；恢复冲突时需保护作者改动并暂停写入。
- App State 的 Undo 历史不是可完全重建数据；缺失时必须诚实显示不可撤销，不影响 Canon 真值。
- 新增写入链涉及多个现有安全模块；必须按 Story 运行质量门，不能依据本次文档自评审宣布实现安全。
