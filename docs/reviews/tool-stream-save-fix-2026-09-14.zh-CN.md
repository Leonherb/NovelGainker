# 保存设定时回复中断：工具响应解析专项修复

日期：2026-09-14。基线：`0b8b6b6`，加本次工作区补丁。仅记录专项缺陷修复，不更新Story/Gate完成状态。

## 实际故障与证据边界

只读检查用户最新两次失败记录：错误均为`provider.protocol`，均仅发起一次Agent请求、没有Compactor、没有工具派发。助手可见文本表示准备读取方法并保存，随后追加未完成提示。因此这两次失败发生在工具执行前，不能解释为候选文件已提交或保存后校验失败。

历史没有保存原始Provider响应，不能确认这两次分别是哪种SSE结构。离线复现找到实际解析缺陷：空`delta.tool_calls`数组被判错；参数增量中的空id/name覆盖或冲突于有效首片身份；一次返回多调用直接终止整轮。修复前空分片回归确实报`provider.protocol`，修复后通过。没有调用真实Provider、读取密钥或修改用户小说。

DeepSeek Chat Completions的工具流为`tool_calls`数组，分片按index配对，身份字段可只出现在首片，见[官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。空身份字段容错属于兼容处理，不据此断言官方实际返回了空字符串。

## 修复行为

- 接受空工具数组；空id/name增量不覆盖已有身份。最终缺少身份、非空身份冲突、损坏封装及参数大小限制仍拒绝。
- 初始工具指令要求每次模型响应最多一个调用，取得结果后再调用下一个。
- NR-5 DeepSeek多调用响应分类为`provider.tool_calls_multiple`。同一执行尝试最多进行一次模型协议纠正：丢弃该响应内全部未执行调用，要求模型改为逐次调用。保留此前完整原生工具结果、可见文本和已提交文件。历史NR-4错误码不变。
- 纠正请求通过原持久请求账本记账，不新建用户消息、轮次或attempt，不重置额度。只有工具仍可用、未取消且至少剩余两次模型请求（纠正调用及后续回复）时继续。重复错误或额度不足如实终止，已提交操作不回滚。
- 取消优先于解析错误及纠正；停止后不再为该错误追加模型请求。

这不是通用网络自动重试：超时、断连、HTTP错误及其他未分类协议错误未加入恢复。阶段调度、目的预算和完整G01～G15实现仍按目标方案推进。不能承诺任何Provider故障下都能生成回复。
