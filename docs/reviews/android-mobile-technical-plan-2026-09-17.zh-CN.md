# NovelGainker 安卓手机版技术方案与访谈结论

日期：2026-09-17。

状态：用户于本会话确认包含一加 12 与 Redmi K70 至尊版的方案，并授权进入实施。当前进入 A 阶段平台准备；安卓编译及真机验收尚未完成，不改变现有 NR Story/Gate 的记录与审批状态。

## 1. 已确认的产品决定

| 编号 | 用户决定 | 实施含义 |
| --- | --- | --- |
| Q1 | 完整核心创作 | 新建工程、AI 创作、手工编辑、查看/确认修改、撤销、章节定稿及本地 EPUB 导出组成首版闭环。沿用已有能力与预算，不扩展为跨轮自动写完整本书。 |
| Q2 | 私有目录工作工程，手动交接 | 安卓工程在应用私有目录运行，系统文件选择器用于工程包导入/导出。整个计划不包含云同步。 |
| Q3 | 后台持续生成必做 | 切换其他应用和锁屏后继续当前任务，提供运行通知及停止操作。系统终止另走 Q6。 |
| Q4 | 签名 APK 小范围使用 | 首版支持本地安装及保留数据的覆盖升级；不包含公开上架和自动分发。 |
| Q5 | 一加 12 + Redmi K70 至尊版（K70 Ultra） | 用户追加 K70 Ultra 为首版支持目标；两机分别真机验收，共用应用代码与计划中的 arm64-v8a APK。具体系统版本、WebView 版本及常用输入法待接入设备时记录，不能由型号推断。 |
| Q6 | 进程死亡后手动继续 | 重开恢复已落盘文字与执行结果，显示中断，由用户点击继续；重开本身不调用 Provider。 |
| Q7 | 自动草稿、手动正式保存 | 编辑内容自动进入可恢复草稿区；显式保存才更新正式 Markdown。草稿不是 Canon，也不是 AI 可引用的新正式版本。 |
| Q8 | 完整可迁移工程包 | 包含稿件、受控资产、聊天及可迁移的撤销/执行记录；API 密钥分别配置，不随包转移。 |
| Q9 | 分叉保留副本 | 目标自交接基线以来未变时可确认更新；两端都修改时并列保留，首版不提供自动或逐文件合并。 |
| Q10 | 允许移动数据 | 换网络后允许继续网络工作；不得重置预算、重放提交或承诺已有连接无缝续传。 |

## 2. 源码事实与复用边界

- React 19 + Tauri 2 + Rust；[Tauri 入口](../../apps/desktop/src-tauri/src/lib.rs)已有 mobile_entry_point，[Cargo 配置](../../apps/desktop/src-tauri/Cargo.toml)已有 staticlib/cdylib。
- [App.tsx](../../apps/desktop/src/App.tsx)已有 900px 以下窄屏分支，[App.css](../../apps/desktop/src/App.css)已有抽屉布局。手机适配可复用业务组件，但不能以浏览器缩窄代替真机验证。
- [ProjectWorkspace.tsx](../../apps/desktop/src/components/ProjectWorkspace.tsx)用 textarea 编辑 Markdown，草稿在 React state；目前没有本方案所需的持久草稿恢复闭环。
- [commands_current.rs](../../apps/desktop/src-tauri/src/commands_current.rs)固定注入 WindowsCredentialVault；[credential_vault.rs](../../crates/app-core/src/credential_vault.rs)非 Windows 分支返回不可用。安卓凭据是必须新增的平台实现。
- [coordination.rs](../../crates/app-core/src/coordination.rs)非 Windows 租约为进程内互斥。现有真实路径、rename/hard_link 等文件操作不能直接使用 SAF content URI。
- [lib.rs](../../apps/desktop/src-tauri/src/lib.rs)窗口销毁会取消任务；项目关闭也会取消。手机 Activity 生命周期不能原样使用此语义。
- 现有可见流式回复未逐段持久化，Provider 原生 Continuation 只在内存。恢复可见文字不等于恢复网络连接或原始协议续接。

上述为静态调查，不构成 Android 编译通过或锁屏任务运行成功的证据。

## 3. 总体架构

```text
共享 React 业务组件
  ├─ Windows 三栏外壳
  └─ Android 对话 / 稿件 / 项目导航
             ↓ 受限 IPC
共享 Rust app-core / domain / 文件事务 / Provider / EPUB
             ↓ 平台接口
  ├─ Windows 凭据、文件对话框、窗口生命周期
  └─ Android Kotlin 桥接
       ├─ Foreground Service 与通知 / 停止 / 生命周期
       ├─ Android Keystore
       └─ Storage Access Framework 导入导出
```

尽量沿用现有应用代码，不复制一套小说引擎。先在现有 Tauri crate 增加安卓目标和平台适配，目录重命名不作为前置工程。业务规则、预算、来源校验、编辑保护和 Committed/Undo 语义共用。

安卓 Activity、前台服务与 Rust 运行协调器采用同一应用进程，不声明独立 android:process。运行状态由应用级协调器持有，不能由某个组件挂载或 Activity 实例拥有。重新创建界面时重新订阅并对账，不能重新启动同一任务。安卓仍须验证进程/实例唯一性，并用应用私有路径上的文件锁补足写者边界；锁只覆盖短事务，不跨网络请求。

平台桥接仅开放封闭的业务动作。新增命令时同步 Manifest、Handler、Permission、Capability、TypeScript 客户端和边界验证；不得通过开放任意文件、URL、进程接口绕过现有合同。

## 4. 后台生成与恢复合同

### 4.1 正常运行

用户在可见界面发起任务时启动前台服务；确认服务可运行后才进入 Provider 调用。服务运行通知提供“打开”和“停止”，默认只显示受控运行状态，不展示小说正文或密钥。结束、失败或需要作者处理时发一次结果通知，并释放服务资源。

前台服务类型优先评估 dataSync，其官方范围包含网络取数和本地文件处理；这是本方案的技术判断，必须在构建验证中确认声明、权限、超时处理和实际任务行为吻合。不使用虚假的媒体/定位任务类型，也不降低 target SDK 规避限制。

按现有单轮、单工程运行和串行工具约束执行。进入后台、Activity 重建、界面切页均不等于作者点击“停止”。返回键先处理键盘和页内导航，回到桌面不自动取消。显式停止/关闭工程仍终止该运行，已经提交的修改保留。

划走最近任务按关闭界面处理，正常情况下继续当前生成；厂商若因此终止进程，则按 Q6 恢复，不能承诺绕过系统强制停止。界面重新加载会话前先查询应用级活动运行；不得将仍由服务持有的 Running 误判为进程中断并改成失败。

Android 前台服务不意味着无限运行或永久联网。目标 Android 15 及以上的 dataSync 存在后台时长限制；必须处理系统超时并保留已持久结果。锁屏验收同时覆盖 Doze、应用电池设置和厂商限制。按需使用有时限、可释放的唤醒锁；不默认要求用户关闭全部系统省电机制，不以唤醒锁承诺绕过 Doze。

### 4.2 流式保存及故障

落实已有目标中的分段持久化：按有界时间/字节阈值保存用户可见文本，带消息、会话、attempt 和递增序号；去重后恢复。具体阈值由性能验证确定并记录。系统可能在两次持久化间杀进程，因此只承诺恢复已确认持久化片段，不承诺最后一个屏幕字符必然落盘。

稿件事务、聊天终态、通知分别记录状态。模型仍在组织最终回复时，已经 Committed 的稿件依然算保存成功；后续网络失败不得抹掉提交。进程恢复先核对事务与回执，未知外部修改进入 recovery_required，不能用重试掩盖。

Q6 的“继续”是作者发起的新一轮、基于持久可见历史及当前稿件继续工作，不是重放原 Provider 请求或复活旧工具授权。原轮的预算/费用/结果保留；新轮明确其身份，重新获取读取与写入依据。不得把隐藏提示、Provider 原生 Continuation 或密钥写进工程以实现续传。

同一存活运行内的暂时网络故障，沿用已批准的有限自动恢复目标及其实现合同；目前代码的零自动网络重试不能描述成已有自动恢复。实施时要求有限次数、累计成本、提交核对；达不到安全恢复条件就终止并保留结果，换网络不重置额度。

### 4.3 必须区分的事件

| 事件 | 目标行为 |
| --- | --- |
| 切应用、锁屏、界面重建 | 当前任务继续；恢复界面只订阅和对账。 |
| Wi-Fi 切移动数据 | 允许联网；断开的请求按有限恢复合同处理。 |
| 点击通知“停止” | 取消后续生成，保留文字和已提交修改。 |
| 系统杀进程、重启、强制停止 | 不承诺运行继续；重开核对状态，由作者点击继续。 |
| 前台服务超时或启动被拒绝 | 明确告知后台不可用/已中断，不显示虚假的后台运行状态。 |
| 存储不足、草稿持久化失败 | 明确显示未备份，不静默丢弃旧记录或冒称已保存。 |

## 5. 手机编辑体验与草稿

三个主入口是对话、稿件、项目；设置集中管理 Provider。文件树、会话列表、执行结果沿用原有业务语义；手机使用全屏编辑和纵向差异比较。桌面继续保持三栏。切页不释放脏稿保护，也不丢失选中文件、光标和滚动状态。

优先验证中文 composition、候选词确认、长按选择/粘贴、撤销、键盘收起、旋转、系统字号、安全区域和手势返回。以逻辑视口布局，不按一加 12 或 Redmi K70 至尊版的物理分辨率硬编码。触摸操作具备明确文字/无障碍名称，常用操作目标按约 48dp 设计。

草稿存入设备本地专用恢复区，绑定工程实例、相对路径、基础文件 hash 和草稿 revision；受 Host 编辑保护及容量限制。独立版本合同，不复用旧工程 v1 重置机制。草稿不进入 Canon 索引、AI 正式上下文、出版或完整工程交接包。

重开时先恢复保护，再展示草稿。基础文件变化时显示冲突，不自动覆盖；显式保存成功后才能清理对应恢复草稿。退出或导出时对未正式保存内容给出保存/放弃/取消选择；“草稿已备份”与“稿件已保存”分别显示。

## 6. 工程存储与双端交接

安卓工作工程保存于应用私有持久目录，SAF 仅在导入导出边界读取/写入字节。系统文档 URI 不进入小说核心。应用专属数据在卸载/清除数据时可能被删除，产品提供清楚的工程导出与备份入口；签名覆盖升级不得清除工程。

Windows 同步补齐工程包导入、导出和冲突识别，否则无法完成已选定的双端交接。首版使用带独立格式版本、文件清单、大小、hash、逻辑工程身份与交接基线的工程包；包版本与现有 Project Metadata schemaVersion 2 分离。

### 包含与排除

- 包含：Markdown Canon、受控资产、允许迁移的项目设置、可见聊天、相关 Task/Change/Publication 记录及支撑撤销的不可变快照。派生记忆按已有格式验证，可安全重建的状态不冒充 Canon。
- 排除：API 密钥、设备绝对路径、隐藏提示、原生 Continuation、设备租约/句柄、未保存草稿、临时文件、可重建缓存以及用户未选择的无关文件。
- 导入的历史记录仅作历史和恢复证据，不能触发执行；待处理意图必须重新验证，不继承其他设备的活动租约、编辑保护或可执行授权。

### 一致性交接

导出前处理脏稿，等待正在提交的短事务完成；有活动生成或 recovery_required 时要求先停止/恢复，不能在不断变化的工程上直接打包。取得稳定快照后释放短锁，再写外部文档。清单 hash 用于完整性/冲突判断，不表示工程包可信或获得执行授权。

导入先解包到受控暂存目录，限制总展开大小、文件数和单文件大小，拒绝路径逃逸、链接、重名/大小写碰撞及不支持的格式。完整校验后才注册或提交；失败不修改已有工程。

有交接基线且本地目标未变时允许确认更新，提交须有日志与恢复备份；目标变化或基线不明时保留并列副本。逻辑工程身份与本机物理实例分开管理，副本的任务/租约不能互相串用。旧版本不兼容时明确拒绝打开或按正式迁移合同复制升级，不能删除内部状态换取兼容。

## 7. 安卓平台与交付

- 凭据：Android Keystore 持有不可导出的加密密钥；Provider 密钥加密存储在本地，原生桥接仅向 Rust 请求链提供短期解密使用，不能返回 WebView。平台桥接的这一受限路径在实施合同中明确，不宣称密钥完全不经过 Android 原生层。
- 备份：禁用本应用系统自动云备份；配置并验证数据转移排除规则，避免系统备份绕过工程包边界迁移凭据或非迁移状态。
- 构建：首版以 arm64-v8a 真机 APK 为交付目标；模拟器构建仅作验证。以 Android 14/API 34 为建议最低版本，实际系统版本先记录再固定测试矩阵。target SDK、NDK、JDK、Tauri 工具链使用实施时核验的兼容组合，版本写入构建记录。
- APK 使用独立的安卓应用标识和稳定签名身份；签名材料不进仓库。交付安装包、校验值、版本说明、备份/升级说明和测试报告。后续升级沿用标识和签名，验证保留工程、设置与凭据。
- 方案确认后可进行实现与本地构建准备；用户已单独确认接受 Google SDK 许可并授权安装构建依赖。真实 Provider 测试、外部分发和应用商店发布仍不自动执行。

## 8. 实施顺序与验收门槛

| 阶段 | 工作 | 完成证据 |
| --- | --- | --- |
| A：平台可行性 | 固定工具链，安卓启动，原生桥接、私有目录事务、Keystore、前台服务最小验证。 | 一加 12 与 Redmi K70 至尊版分别能安装启动；合成任务切后台/锁屏运行；记录系统/WebView/电池设置；验证凭据和文件能力。未通过不宣称总体可交付。 |
| B：运行与恢复 | 应用级运行协调、前台服务、停止/超时、分段回复、持久草稿、进程恢复。 | 合成 Provider 下验证中断、提交前后杀进程、已保存结果、重开零网络调用、无重复副作用。 |
| C：工程交接 | 双端包格式、稳定导出、受控导入、基线检测、并列副本、历史/Undo 可迁移性。 | Windows → Android → Windows 往返；冲突、坏包、不兼容版本、空间不足和导入中断均保护已有工程。 |
| D：手机创作闭环 | 导航、全屏编辑、差异确认、会话、定稿、EPUB、中文输入与键盘布局。 | 真机完成建工程至 EPUB 导出；切页/键盘/旋转不破坏草稿；AI 写入不覆盖手工内容。 |
| E：可安装交付 | Release 签名 APK、覆盖升级、使用说明、设备验收报告。 | 相同签名覆盖升级保留数据；冷启动恢复正确；后台与电量/网络场景报告具备实际证据。 |

安卓自动化使用隔离合成工程及本地测试 Provider。模拟器/USB 测试网络只能使用受控测试配置，不扩大生产网络权限；不得自动使用真实稿件或真实 Provider 凭据。需要真实模型语义验证时由用户自行操作并提供脱敏结果。

各实现阶段按仓库要求运行 pnpm quality，Rust 验证保持 --locked --offline；离线编辑回归运行 pnpm e2e:sprint1。安卓新增构建/设备验证另记录，桌面测试成功不能代替安卓证据。当前文档工作只检查事实、引用与 diff，不宣称代码质量或设备测试已通过。

后台真机验收至少覆盖：前台生成、切其他应用、锁屏短测及长测、系统空闲/Doze、常用电池设置、Wi-Fi 与移动网络切换、断网、通知停止、划走最近任务、Activity 重建、系统杀进程及强制停止。各事件分别记录预期与实际，不将主动强制停止后的不运行判为可无限保活的缺陷。

新增 Redmi K70 至尊版以共用代码和安装包为目标，主要增加 HyperOS 环境的后台运行、锁屏通知、应用电池限制、键盘/布局、文件选择、Keystore 与覆盖升级验证。不得由一加 12 的通过结果推定 K70 至尊版通过；任一机型未实测时，只能标为计划支持。先验证系统默认设置，仅在实测出现限制时提供该设备必要的设置指导，不自动索取自启动或电池优化豁免。

首次 APK 可行性验证完成后，再根据编译依赖、厂商后台行为与现有测试结果细化工期；本方案不对尚未验证的平台工作给出确定完成日期。

## 9. 收敛状态

产品分支已由 Q1—Q10 决定；用户已确认整体共同理解，按本文实施顺序和技术默认值推进。不重复询问既定产品取舍，完成状态仍以实际代码和验证证据为准。

尚待采集的是设备/工具链事实：一加 12 与 Redmi K70 至尊版各自的实际 Android 与厂商系统版本、WebView、常用输入法及后台限制设置。它们用于固定构建与验收环境，不重新询问已确认的产品取舍。若设备验证证明某项核心要求无法满足，再携带实测证据讨论替代方案。
