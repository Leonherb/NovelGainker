## 3. NR-5-D1：章节、连续性与出版

目标：让用户自然讨论、准备候选、正式保存章节、按正式章节维护资料并导出本地 EPUB。技术退出 NR-G6。

### 3.1 状态、身份与正式来源

- `discussion` 只在对话；`candidate` 为未保存候选；`committed` 表示实际章节文件已写入。frontmatter 的 `status: draft|final` 表示出版就绪程度，与“已落盘”分开。保存了 draft 不等于 final，也不等于已经出版。
- `ChapterCandidate` 必须绑定 projectId/sessionId/turnId、当前用户提交来源、完整候选 Hash/版本、章节目标及预期旧 Hash。代词“就这版”必须能定位已展示的具体候选；不能把模型自述“你已确认”当来源。
- 用户明确“写并保存第 N 章”可直接形成提交来源，不强制另点按钮；仅要求讨论/试写/评审不自动提交。歧义、冲突、改编号、改身份、清空和大范围替换必须询问。
- 章节沿用模板 kind=chapter、schemaVersion=1、writingLanguage=zh-CN、UUID、title、chapterNumber 与唯一 `## Draft`。Host 分配新身份/安全路径，章号为正整数；同工程重复身份/章号拒绝，空号不自动重排。
- 每次正式提交留 `ChapterCommitReceipt`：projectId/chapterId/transactionId/revision/beforeHash?/afterHash/sourceReferences/状态；真实磁盘与提交标记一致后才签发。手动保存合格章节须纳入同一协调与回执。
- 已存在但无回执的章节，不因一次只读就取得“正式提交来源”；用户明确认可现有版本时，可做有来源的 no-change adoption 并签发绑定当前 Hash 的回执，不重写稿件。普通只读仍可读取它。
- 章节独立来源需 project + chapterId + commitId/revision + 当前 afterHash + 已交付阅读证据。被撤销、已修改、未决恢复或外工程的回执不可复用；不能靠伪造 Hash 自动生成凭证。
- 章节变更与资料维护是两个独立变更集。资料维护失败不撤销已提交章节；章节 Undo 后既有依赖资料标记需要复核，不静默连带 Undo、也不继续使用失效来源。应用重开不得自动发起未获新授权的 Provider 调用。
- NG-F01：定稿确认须由持久的用户决定来源绑定projectId/chapterId/commit revision/afterHash，不只信任`status: final`。应用内保存正文修改时，在同一受保护事务中回到draft并使旧确认失效；如果用户明确同时确认修改后的具体版本定稿，可签发新确认，但不能复用旧确认。外部修改被发现后只标“需要重新定稿”，不擅自重写文件。历史final无有效确认需显式采纳该版本；只读不自动补发。已失效确认不因重开或Undo字节相同自动复活。出版前须重新核对当前文件与确认版本；Hash规范、状态字段写入顺序及无正文变化的处理在NR-501合同中冻结，避免确认记录自包含Hash。

3. final 状态修改需用户决定来源；历史章只有 Draft 内容合格但没有 final，不能静默发布。封面缺失允许“无封面 EPUB”并清楚提示；不自动图生图、不下载图片、不把 create-visual-asset 当已挂载。
4. 选定输入在一致视图下冻结 Hash/字节；构建只消费该快照，完成时重检变化并标记 stale 或拒绝当前版发布，绝不把混合版本命名最新书稿。
5. XML/Markdown 转义、目录/spine 顺序、资源引用、ZIP 条目路径与有界输入输出通过正反例。离线外部合规验证器只可作为固定测试依赖，不进入应用运行时；不能把自制检查器称为完整第三方认证。
6. 只生成 Host 命名的 `published/{buildId}.epub` 与安全回执，已有产物不覆盖；构建中断保留旧产物，清理仅精确本次临时目录。列表/详情用 opaque artifactId，不接受模型任意导出路径/URL。
7. 终态列为“已生成/验证失败/已过期”，不假装已上架。验证前后 Canon 总 Hash 相同，History/Memory/Task/密钥不在 ZIP 中。
8. NG-F01验收：构建输入逐章匹配有效定稿确认和当前Hash；正文变更后残留final字段、旧确认、跨章确认都不能出版。预检/构建间变化拒绝或标过期；故障仅阻断本次出版，不抹掉普通回复，不否认既有产物。

出版元数据取工程已有 `project.md` 的 title/author/writingLanguage 等批准字段；缺失时提示通过已有手动编辑补齐，不临时开放 root 任意 AI 写通道。构建有界白名单 Markdown 子集，排除脚本/原始危险HTML/远端资源，未知语法清楚提示而非静默损稿。输入资产按签名/MIME/尺寸一致性核验，不执行主动内容。

### 4.1 拟冻结共用选择

- 清空默认可恢复归档旧 Session并新建空 Session，不物理销毁仍被 Change/Chapter 来源引用的消息；明确告知用户这不是安全擦除。首版不提供强制永久清除历史。
- branch 复制选定的完整已结束 Turn 前缀，分配新 Session/Turn/Message ID，并留 parent reference；不复制可执行 Tool 请求、待确认写权限或 Memory。原始 Change/Undo 留在原记录可查，新分支共享当前 Canon而不是恢复过去 Canon。
- 拟增7项封闭IPC：conversation_session_list/create/rename/activate/branch/clear/export；基于NR-5共37条。clear的封闭动作含archive（只归档）、archive_and_create（清空）、restore；不能传任意删除路径。候选名须长度/字符约束。归档当前会话后只切换视图到已有非归档会话或空态，不自动调用Provider。
- 导出在系统文件选择授权后由 Host 消费一次性目标 token，模型只得到 opaque exportId；输出可见 Markdown/JSON 对话，不导出 hidden prompt、工具原生协议、凭据、内部状态。选择目标不授权覆盖既有文件。
