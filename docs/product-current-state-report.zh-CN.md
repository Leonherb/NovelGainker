# NovelGainker 当前产品与实现状态

核验日期：2026-09-09。源码基线：`34f4e39219d7749aaa10fd640eee22f6ec634357`。本文描述可核对的当前实现；目标产品另见[重整策划案](product-spec.zh-CN.md)，访谈与差距见[梳理记录](reviews/project-reframe-2026-09-09.zh-CN.md)。

## 当前可用能力

应用为Windows、本地工程、简体中文小说工作台。三栏为工程/文件/会话/Provider、自然聊天、真实Markdown编辑器。左右侧栏支持拖动调整宽度，多会话位于左侧文件树与Provider之间。

| 能力      | 当前实现与边界                                                                       |
| --------- | ------------------------------------------------------------------------------------ |
| 自然对话  | 使用固定的DeepSeek/OpenAI配置，模型自主选择方法及工具；普通聊天可零工具              |
| 内置方法  | Novelist应用投影1.4.0，9能力/37资源；内置方法不等于全部具有可执行工具                |
| 实际工具  | read_context、propose_change、publish；图片生成没有执行器                            |
| 文件维护  | 人物、世界/设定、素材、剧情、大纲和单章；严格来源、完整读取与版本校验                |
| 保存/撤销 | Host持久提交回执、Diff、确认和可恢复Undo；模型文字与Task成功不代替保存证据           |
| 章节/定稿 | 每轮至多一章，完整章节32 KiB；定稿绑定版本，修改或Undo使原定稿依据失效               |
| 本地EPUB  | 已实现预检与构建，仅消费当前有效定稿及受控资产；不是平台上架或第三方认证             |
| 多会话    | 32个非归档、256个总目录条目；会话隔离历史/记忆/Task，共享当前稿件；同工程一个运行    |
| 历史操作  | 命名、切换、聊天分支、可恢复清空/归档、导出；聊天分支不回滚稿件                      |
| 工具详情  | 已有内联折叠记录，显示工具、状态、时间、编号和受控错误；不提供原始协议或完整执行回放 |

## 当前执行和数据约束

一次消息最多8次Agent请求及1次Compactor，4次读取、2次变更、1次出版，累计请求输出上限33792 tokens。五类资料一次至多4目标/8 KiB正文；工具参数和结果各64 KiB，续接512 KiB、实际请求体768 KiB。最后一次模型请求不开放工具。

这是一轮有界执行，不是跨轮自动完成整个创作阶段。当前对话没有自动网络重试，仅符合条件的零输出、零工具失败可由用户显式重试一次，并沿用原预算。进程重开不自动继续调用模型；屏幕上的流式片段并非每段都已持久化。

| 内容                  | 权威与存储                                                 |
| --------------------- | ---------------------------------------------------------- |
| 小说Markdown/受控资产 | 唯一稿件来源                                               |
| Conversation          | 用户可见历史，按项目内会话保存                             |
| Memory                | 从可见历史派生的可丢弃摘要，不等于完整记忆                 |
| Task                  | 受控状态、哈希和字节数，不保存原始工具参数/结果            |
| Change/Publication    | 实际快照、提交和产物回执；只有当前有效证据支持对应成功声明 |

更新采用版本和编辑保护；外部改动、脏稿或未决恢复不强制覆盖。文件已提交后，后续回复失败不能否认保存。恢复未决可能阻止新写入，但不应借此禁止普通对话。凭据仅由Rust使用Windows Credential Manager，不由UI读回。

## 完成度与验证口径

既有实施记录为NR-501～506、NR-601～603共9/12项Story完成；NR-604～606及最终NR-G7尚未完成。历史质量门结果见[实施记录](reviews/novelist-agent-runtime-nr5-nr6-implementation-log.zh-CN.md)，不能把它们当成每个后续补丁都已完整复验。

用户已经直接试用并反馈过故障，因此不再笼统写“无人实测”。正式多用户、双Provider语义、30万/100万字长篇、干净安装/旧工程升级及最终版本复验仍没有完整通过证据。离线脚本只证明受控输出下的Host和协议行为，不证明真实模型意图理解或小说质量。

本次仅做只读源码审计和文档整理，没有运行新测试、修改生产代码或调用真实Provider。

## 当前差距

- 当前代码没有阶段计划、阶段授权、暂定事实验收及跨轮持续推进机制。它们属于本次重整目标。
- 2026-09-09复核时未找到此前文字交付所述的自动模板修复；2026-09-10已重新实现NR-5必需模板自动交付及有界参数类型/枚举诊断。验证和构建以[实现切片A记录](reviews/implementation-slice-a-2026-09-10.zh-CN.md)为准，不能推断旧EXE已有修复。
- 候选格式失败已补充模板入口、元数据差异和换行提示；逐候选结构化错误、Host统一装配创意内容仍待后续实现。有限自动恢复、预算优先及重开确认后继续尚未按新目标改造。
- 归档历史与Undo操作、分支中的历史工具证据、长期容量释放路径和语义验收统计口径需要明确。
- 没有工程云同步需求；不把图片生成、平台上架或后台无人值守作为已交付能力。
