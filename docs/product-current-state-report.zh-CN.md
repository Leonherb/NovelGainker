# NovelGainker 当前产品报告

更新日期：2026-09-05；版本：0.1.0。现行实现已到 NR-4，NR-401～406 各自完整质量门通过，NR-G5 已获产品批准。后续 NR-5～NR-6 共12项Story已形成并自评，尚未实施，不计入下列现行能力。

## 已实现

应用保持三栏：工程/文件/Provider、自然聊天、Markdown 编辑器。新工程无需预先有人物或章节；完整可见聊天随工程保存，Memory 是可丢弃摘要。

内置 Novelist 为应用自有投影 1.1.0，九能力、37 资源。模型按语义决定是否取方法、查 Canon 或维护资料；用户不需要选择 Skill。写权限工程有一个只读工具和一个受约束变更工具。没有调用工具的普通回复不能显示 Host 已保存。

| 体验 | 实现与边界 |
| --- | --- |
| 资料维护 | 人物、世界/设定、素材、剧情、大纲五类；新建、更新、无变化判断 |
| 明确决定 | 通过真实来源/方法/完整读取/Hash 校验后可自动保存 |
| 不确定变化 | 只留对话、待确认或拒绝；AI 建议不自动成为用户决定 |
| 保存证据 | 简短 Host 回执、实际原文/候选 Diff，而非相信模型说“已完成” |
| 冲突保护 | 旧 Hash、旧 revision、同名歧义、手工编辑占用不强制覆盖 |
| Undo | 按变更集撤销；所有目标须仍匹配保存后版本；逆事务可恢复 |
| 聊天失败 | 已生成内容保留；提交后 Provider 失败不否认已保存文件 |
| 关闭 | 仅手工未保存 Markdown 能阻断；AI 待确认草稿不增加关闭弹窗 |

## 如何辨别实际保存

查看当前回复内的“资料保存结果”。“已保存 N 项资料”来自 Host 的持久 Committed 回执；“待你确认，尚未保存”表示候选未落到 Canon。“查看更改”展示实际原文与候选差异；“撤销本次更改”不请求 Provider。

仅显示“已完成”通常是聊天/任务终态，不能单独证明文件已经改变。模型自述调用失败也不能替代 Host 记录。结果加载失败会单独提示并允许重试，不阻断聊天。

正在聚焦的干净编辑器也保守保留写入占用；离开后干净内容释放，脏草稿继续受保护。遇到过期候选，请先保存/放弃手工稿，再让 AI 重新读取并准备，不存在强制覆盖。

## 数据与安全

Markdown 与 assets 是唯一 Canon。`.novelgainker/` 分开保存 Conversation、派生 Memory、Task 状态和 Change 快照/回执，不进入小说索引/出版。Key 仅由 Rust 使用 Windows Credential Manager，UI/IPC 不能读回。

一次变更最多四目标、候选合计 8 KiB。变更库 64 MiB / 100 记录 / 10 待确认，满额不会静默删除 Undo 或作者内容。丢失快照后不能重建历史 Undo。外部修改导致无法恢复时保留全部证据，停止写入；只读工具和聊天可继续。重试安全恢复仍只允许已知版本，完成后重开工程刷新写权限状态。

## 尚未交付与已知限制

- NR-5 正式章节写入及独立章节来源维护未开放；NR-4 可处理用户明确引用章节的资料更新，不修改章节文件。
- 有九项能力的方法资料，不代表九项都有可执行工具：例如图像生成、出版、完整连续性闭环不因方法存在而自动获得执行环境。
- 自动化只验证受控 Provider 输出下的 Host/协议与事务行为；真实 DeepSeek/OpenAI 意图识别、Skill 选择、摘要及写作质量尚未正式验证。
- 最小只读 Live Smoke 已由用户明确放弃并接受风险；NR-6完整验证改为多用户直接试用，见[测试方案](testing/novelist-agent-runtime-nr6-multi-user-test-plan.zh-CN.md)。R04前三项产品行为已接受；尚未发放或执行测试，不等于真实Provider兼容性已通过。
- AI 更新当前限可证明原始字节与规范化文本一致的小型 UTF-8 文档；不安全地转换编码或截断大文件不是回退方案。
- 不保证任意外部编辑器看见多文件原子变化；只保证应用内协调与可恢复部分失败。
- 多会话分支、Provider断点续传不在NR-4范围。云同步不是用户需求，已从整个计划移除，不列为未来功能。

五项补漏方案NG-F01～NG-F05已获用户接受并落实到后续Story验收，包括32个非归档名额（归档计总存储）。这是设计决定，不改变上述当前生产能力；内联工具详情、定稿失效、完整链及安装升级/最终版复验均待后续实施。
