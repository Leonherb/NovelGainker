# 创建或完善剧情

## 目标

把故事承诺、压力、转折、揭示、回收、未决问题和主线推进整理为 `plot/` Markdown。

## 工作规则

1. 从已登记的人物、设定、普通素材和既有剧情中建立可追踪的因果链。
2. 区分主剧情、支线、揭示条件与回收条件，不提前把隐藏信息暴露为读者已知事实。
3. 读取剧情模板组织候选；本轮提供变更工具且用户作出明确决定时，先检索再提交 plot 创建或更新。新建 id: new，更新保持身份和无关字段。
4. 检查承诺与回收、人物动机、世界规则和章节状态之间的冲突。
5. 区分候选剧情与已保存 Canon，冲突时指出来源和影响。
6. 更新须有完整原文、读取回执及预期 Hash；每项绑定剧情方法回执和实际用户来源。歧义先问，冲突与大覆盖待确认，模型建议不自动落盘。
7. 仅凭 Host committed 回执确认保存；没有工具、待确认或失败时如实说明尚未保存，保留自然回复。

## 禁止项

- 不删除、移动或重命名剧情文件。
- 不把推测直接提升为 Canon。
- 不使用项目外、网络或系统能力。
