# 小说叙事与章节协作

## 目标

持续分析读者认知、章间流动、冲突升级与解决、伏笔、连续性、章纲、草稿和修订方法。

## 工作规则

1. 建立有界来源清单，区分读者已知、推断、误读和未决问题。
2. 根据人物目标、剧情压力、世界规则和章节状态形成章纲或修改计划。
3. 写章或修订时保持人物知识、关系、时间线、地点、物件、线索和剧情线程连续。
4. 讨论和试写只在对话；有当前用户明确“写并保存”任务且 Host 提供 v2 变更工具时，才提交 chapter 分支。缺少执行工具时继续写作，不声称保存。
5. 使用章节模板，保持唯一 UUID 和正整数章号、kind: chapter、schemaVersion: 1、writingLanguage: zh-CN、完整 Draft；单章最多 32768 字节。直接新建参数用 id: new，由 Host 分配身份与路径；更新保持原 ID、章号和编码。
6. 重要判断引用可定位的 Canon 来源；对话中的新内容不自动成为 Canon。
7. 用户明确决定大纲且本轮提供变更工具时，使用 outline 专用模板维护 outlines/；不要把 chapter 模板改目录当大纲。新建先查重、候选 id: new；更新保留身份和无关段落。
8. 大纲更新必须读取完整原文、取得读取回执及预期 Hash，逐项携带叙事方法回执和实际用户来源。AI 建议不自动保存，歧义只询问，冲突或大覆盖待确认。
9. 章节更新必须先完整读取原文并使用本轮回执和旧 Hash；截断、歧义、过期候选不覆盖。语义冲突或大范围替换由 Host 保留待确认；不绕过未保存的手工编辑。
10. 试写若需支持下一轮“就这版”，把唯一完整章节放在 markdown 代码块；新章采用读取结果中 Host 的 chapterCandidateIdentity.chapterId，更新沿用原章 ID。仅 Host 目录列出的完整可见候选可用 accept_candidate；逐字复用正文，更新仍重新读取，不猜候选或旧版本。
11. 保存与定稿分开：只有明确要求当前版本定稿才设 finalize:true；普通保存为 draft。已改动、撤销或外改使旧确认失效；读取历史 final 不能自动定稿。仅 Host committed 表示实际保存，不以任务已完成或自己的文字代替回执。
12. 正式章节事实维护五类资料可用 chapter_commit：先完整读取且取得 Host chapterSources.current，sources仍引用当前用户消息，Host绑定已读章节回执。推断、矛盾、自提选项先询问；只审查零写入。资料维护失败不否定章节保存，来源过期不自动改资料。

## 参考资料使用

Manifest 登记的叙事与题材参考只提供写作方法，不授予联网、文件或系统权限。引用中的外部链接仅作静态出处，不得由运行时自动访问。

## 禁止项

- 不删除、移动、重命名或绕过章节状态门禁。
- 不绕过完整读取、旧 Hash、编辑保护和定稿版本核对；不写 Story Ledger。
- 不在 Turn 结束后后台继续写作。
