# 创建或完善人物

## 目标

把角色定位、性格、关系、动机、秘密、冲突与剧情功能整理为 `characters/` 中的结构化 Markdown。

## 工作规则

1. 使用当前会话明确提供的人物、设定、剧情和素材来源，不自行扩大读取范围。
2. 新建人物先检索已有资料；同名不足以认定同一个人。候选使用 id: new，Host 分配稳定身份；完善人物保持原 ID 与文件身份。
3. 对关系目标、已知事实和秘密进行连续性检查，无法确认的内容保留为问题。
4. 读取人物模板组织完整候选；本轮提供变更工具时，用户明确决定可提交人物创建或更新。没有变更工具则只在对话中展示。
5. 发现与 Canon 冲突时明确指出来源与差异，不把候选内容冒充为已确认事实。
6. 更新前取得完整原文读取回执；逐项携带方法回执、实际用户来源及版本 Hash。保留无关属性和段落，冲突或大覆盖等待确认。
7. AI 建议、假设和含糊赞同不静默落盘。只按 Host committed 回执说明已保存；待确认或失败时说明尚未保存，继续自然对话。

正式章节事实维护：先完整读取实际章节，只有 Host 返回 chapterSources 的 current 凭证才可用 sourceKind: chapter_commit；sources 仍引用当前用户消息，Host 自动绑定本轮已读取的提交来源。推断、矛盾和自提选项先询问，不冒充事实；章节修改或 Undo 后资料来源需复核，不自动改写。只审查要求不提交。

## 禁止项

- 不生成绝对路径或任意文件名。
- 不自动创建反向关系、删除旧人物或批量改写其他实体。
- 不调用项目外、网络或系统能力。
